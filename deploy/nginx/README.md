# Public-surface nginx vhosts

The nginx configuration for the project's **own** three public surfaces:

| Host | Serves | From |
|---|---|---|
| `dockpanel.dev` | the marketing SPA | `website/client/dist` |
| `demo.dockpanel.dev` | the live panel demo | `panel/frontend/dist` |
| `docs.dockpanel.dev` | the mdbook output | `docs/book` |

These are **not** what a DockPanel install uses. A real install's panel vhost is
generated by `scripts/setup.sh` and migrated in place by `scripts/update.sh`;
the container templates are `panel/frontend/nginx.conf` and
`website/client/nginx.conf`. This directory is the config for the three sites we
host ourselves, which nothing else in the repo described.

## Why they are here (s281)

Until s281 these files existed only on the box that serves them — hand-edited,
no history, no review, and no way to rebuild the machine from anything. Three
sessions of cache-header work (s278, s279, s280) lived exclusively in them.

Committing them also made a real defect visible in about a minute: the s278
`no-cache` fix had been applied to `dockpanel.dev` and **not** to
`demo.dockpanel.dev`, which sits in the same file and had the identical bug.
Nothing on the box could have shown that, because there was nothing to diff.

## Placeholders

The repo copies are rendered, not copied. Two host-specific values are
substituted out — not because they are secret, but because this repository is
public and neither belongs in it:

| Placeholder | Meaning |
|---|---|
| `__ORIGIN_IP__` | the origin's own address on its LAN |
| `__SITE_ROOT__` | the checkout the three sites are served from |

Neither is configured. `sync-site-vhosts.sh` derives the address from whatever
the live vhosts already bind (falling back to the box's own route), and the root
from the checkout it is run in, so the script works unchanged on any origin —
and the value never has to be written down anywhere in this repo.

## Keeping them honest

```bash
scripts/sync-site-vhosts.sh          # check — does the repo still match the box?
scripts/sync-site-vhosts.sh --pull   # adopt the box's current config
scripts/sync-site-vhosts.sh --push   # write the repo's config to the box
```

`--check` runs in CI (`nginx-contract`). Off-box it cannot diff, so it asserts
the copies are present and carry no host-specific value instead of passing
silently — a check that quietly succeeds when it cannot see its subject is the
failure mode this whole session was about.

**After editing on the box, run `--pull` and commit.** Nothing enforces that
from the box's side; a config edited in place and never pulled is exactly the
state this directory exists to end.

## The `:443` trap

Every `listen` here names the interface explicitly (`__ORIGIN_IP__:443`) rather
than binding the wildcard. A wildcard `:443` makes that vhost the de-facto
default for the address, and Cloudflare returns **526** at the edge for the
siblings it shadows. `certbot --nginx` writes a wildcard listen when it touches
a file, so re-check after any certbot run.

## The header contract

Both files repeat the server block's security headers inside every `location`
that sets any header of its own. This is **not** redundancy: a location block's
`add_header` directives *replace* the server block's set rather than merging
with it, so a block that sets one cache header and nothing else silently strips
every security header off those responses. That is precisely how
`dockpanel.dev` came to serve its JS bundles with no `X-Content-Type-Options`.

The contract is pinned by `tests/nginx-headers-pin-e2e.sh`, which serves the
real templates through a real nginx — and asserts a `200` before reading any
header, because these headers are `always` and nginx emits them on error pages
too.
